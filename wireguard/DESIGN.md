# WireGuard 管理工具设计文档

> 配套实现脚本：`wireguard/wg-server.sh`（服务端）、`wireguard/wg-client.sh`（工控机端）。
> 面向用户的使用指南见同目录 `README.md`。

本文档记录的是「做什么、为什么这样做」，不重复脚本源码里的注释。

---

## 1. 定位与边界

### 1.1 这套脚本是什么

hub-and-spoke 中心化 WireGuard 虚拟局域网的 **配置与密钥管理工具**。

核心能力：

- 密钥生成与管理（服务端、客户端各自持有私钥，私钥永不出本机）
- `wg0.conf` 的结构化增删（以服务端配置为唯一的 Peer 注册源）
- 地址段的分配、回收与冲突校验
- 交互式启停与状态查询（菜单 + 子命令双模式）
- 启停、分流检查、健康提示等运维辅助

### 1.2 这套脚本不是什么

脚本 **不** 做以下事情，这些仍由人工按操作指南（见仓库《使用原生 WireGuard 搭建中心化虚拟局域网》文档）完成：

- 不安装 `wireguard`、`iptables`
- 不开 `net.ipv4.ip_forward`
- 不放行 UFW / 云平台安全组 UDP 51820
- 不做 NAT、不做互联网出口
- 不跨机器清理对端配置（脚本碰不到远程工控机）

边界这样划的原因：各地工控机/云服务器镜像、网络差异大，网络层变化容易翻车；安装与网络驱动是「人读教程」该承担的，脚本只做确定性的「配置与密钥操作」。

### 1.3 脚本在仓库中的位置

```
wireguard/
├── wg-server.sh       # 服务端脚本
├── wg-client.sh       # 工控机端脚本
├── DESIGN.md          # 本文档：设计决策 + 术语
└── README.md          # 面向用户的使用指南
```

总入口 `sh-tools.sh` **先不挂** WireGuard，列表已经 7 项会挤，且 WireGuard 是成对使用、语义和单点工具不一致。稳定后再决定。

脚本仅支持本地执行（会检测自己是不是通过 pipe/stdin 远程跑，是则拒绝并提示 clone）。原因是脚本必须碰 `/etc/wireguard/` 才有价值，远程单文件跑没意义。

## 2. 术语表

先把全文会出现的关键概念固定下来，避免 README 和脚本菜单里叫法飘。

| 术语 | 含义 |
|---|---|
| **hub-and-spoke** | 拓扑结构。公网服务器是 hub（中心），所有工控机/管理电脑是 spoke（辐条）。spoke 之间通信经 hub 转发，不打洞 |
| **wg0** | WireGuard 接口名。服务端、客户端统一叫 `wg0`，绑定的服务是 `wg-quick@wg0` |
| **wg0.conf** | WireGuard 配置文件，默认 `/etc/wireguard/wg0.conf`。**Peer 注册的唯一权威源** |
| **Peer** | WireGuard 对等体。服务端配置里每个 `[Peer]` 块就是一个真实节点（一台工控机或一台管理电脑） |
| **hub 脚本** | `wg-server.sh`。跑在公网服务器上 |
| **spoke 脚本** | `wg-client.sh`。跑在工控机或管理电脑上 |
| **结构化读写** | 对 `wg0.conf` 的操控范式：解析成内存结构 → 增删 → 统一格式化写回，不靠正则原地编辑 |
| **地址段** | VPN 网段里按设备类型切出的 IP 范围（管理电脑 / 工控机 / 预留） |
| **空闲 IP** | 某地址段内未被任一 Peer 占用、可供新节点分配的 IP |
| **syncconf** | `wg syncconf wg0 <(wg-quick strip wg0)`，热加载 Peer 变更而不中断已有连接 |
| **原子写回** | 写配置前先 `.bak` 备份再写临时文件再 `mv`，避免中途出错毁配置 |
| **双模式** | 菜单循环（默认，无参数启动） + 子命令（带参数启动）并存 |
| **二次确认** | 危险操作（删 Peer）前要求用户再次输入确认 + 展示将被影响的完整信息 |
| **在线警告** | 二次确认的特例：若待删 Peer 30 秒内握过手（在线），额外再警告一次 |
| **僵尸 Peer / 孤儿 IP** | 配置与运行时不一致的状态，作为健康提示来源 |
| **分流模式** | 客户端 `AllowedIPs = 10.77.0.0/24` 的产物：仅 VPN 网段走 WireGuard，其余走原网关 |
| **init 向导** | 工控机端菜单项，交互式生成 wg0.conf 并可选立即启动 |
| **Endpoint** | 客户端配置里 `Endpoint = 服务器公网IP:51820`，客户端唯一需要知道的服务端信息 |
| **PersistentKeepalive** | 客户端每 25 秒发保活包，维持 NAT 映射 |
| **流式公钥传输禁忌** | 私钥（尤其客户端私钥）绝不经网络/聊天传输，只在本机生成与持有 |

## 3. 设计决策

下面是每个关键决策及其背面被否掉的选项。每个决策编号对应一次对齐讨论。

### D1 — 脚本的核心职责

- **选定**：配置与密钥管理工具（A），加上交互式启停/状态查询
- **否掉**：也驱动系统安装（B）、完整生命周期含抓包排障（C）

理由详见 1.2 边界。启停值得保留是因为 `systemctl` 需要 root 且几个子命令，菜单能把它做得比裸敲 systemctl 更省心；抓包不值得是因为 `tcpdump` 用法多样、留给人工。

### D2 — 脚本拆成两个

- **选定**：拆成 `wg-server.sh`（服务端）和 `wg-client.sh`（工控机端），各自一份菜单

理由：服务端管多 Peer 注册，工控机端只管本地配置+启停，职责差异大，塞一个脚本会太重；各拿一份菜单、各自可独立在对应机器上跑。

### D3 — Peer 注册存在哪

- **选定**：`wg0.conf` 本身即注册表（结构化读写）
- **否掉**：独立清单文件（JSON/csv/每Peer一文件）+ 渲染成 wg0.conf

理由：

- 和《使用原生 WireGuard 搭建中心化虚拟局域网》文档的用法完全一致，人不需学新格式
- 一份文件、人类直接可读可编辑、出了问题直接 `nano wg0.conf` 能救
- 清单+渲染是 Ansible 思路，对这个场景是过度设计

### D4 — IP 分配策略

- **选定**：地址段内取最小空闲 IP + 手动指定兜底
- **否掉**：纯随机/哈希

理由：紧凑好记（第一台工控机一定是 .11，第二台 .12），符合按段规划直觉。自动分配前强制校验整个 wg0.conf 里 `AllowedIPs` 不冲突——因为人可能手工改过配置，不能只相信脚本自己记的。

附加：删 Peer 回收复用 IP（把该 IP 放回空闲池），回收前需二次确认 + 展示原持有者信息，防误删。IP 只增不减（永不回收）被否决，原因是工控机段只 189 个地址、是有限资源，设备增长是常态。

### D5 — 配置路径、权限、缺装处理

三条子决策：

- **D5.1 路径**：可改变量 + 默认值 `WG_CONF="${WG_CONF:-/etc/wireguard/wg0.conf}"`，可被命令行/环境变量覆盖，便于离线测试不碰真配置。
- **D5.2 root**：自检 `EUID`，非 root 则 `exec sudo "$0" "$@"` 重执行。纯只读项（查看公钥、分流检查）提示用户"只读无需 root，继续？(y/n)"做优雅降级。
- **D5.3 缺装**：检测失败就打印安装命令 `sudo apt install -y wireguard iptables` 并退出；不自动安装。保留纯只读菜单项照常运行的能力（只要之前生成过密钥）。

### D6 — 地址段配置化

- 脚本顶部变量：`WG_SUBNET="10.77.0.0/24"`、`WG_SERVER_IP="10.77.0.1"`、`ADMIN_RANGE="2-10"`、`IPC_RANGE="11-199"`、`RESERVED_RANGE="200-254"`
- 下个项目换网段只改顶部
- 启动时自检「每个地址段是否落在子网内」，配置错了一开始就报错

### D7 — 删除 Peer 的定位与善后

- **定位**：菜单序号为主、IP/公钥精确匹配为辅（脚本化引用）
- **二次确认**：展示 IP + 公钥 + 角色 + 上次握手时间
- **在线警告**：上次握手 30 秒内→再警告一次「该设备当前在线，删除会立刻中断连接」
- **善后**：不跨机器清理（脚本碰不到远程工控机，越界），但打印「请在对端手动清除 wg0.conf 或停止 wg-quick」的提示

配套的「查看状态」健康提示：

- IP 冲突检测
- 有公钥但从未握手→可能未生效/对端未配置
- `wg show` 里有握手但 wg0.conf 没有→运行时 Peer 与配置文件不一致

### D8 — 公钥传输路线

- **选定**：工控机端本地生成密钥对，操作员把公钥抄给服务端粘贴
- **否掉**：服务端代为生成再下发（私钥经网络传输泄露面大）

操作闭环：

```
服务端  ./wg-server.sh add-peer   → 要操作员贴公钥
工控机  ./wg-client.sh init      → 生成密钥对，屏幕显示公钥（高亮/剪贴板）
         ↕  （操作员来回抄一次公钥）
服务端  粘贴工控机公钥完成添加
```

init 完成后提示「是否立即启动连接？(Y/n)」，确认后 `systemctl enable --now wg-quick@wg0`，紧接着自动跑 `wg show` + `ping -c 3 10.77.0.1` 让用户看到连通结果。

### D9 — 写回安全与生效方式

三条子决策：

- **D9.1 服务端私钥**：解析时从现有文件读出，写回时原样照抄，脚本全程不要求用户输入、不打印、不日志化服务端自己的私钥。服务端私钥只由安装时一次性生成。
- **D9.2 原子写回**：写前 `cp wg0.conf wg0.conf.bak` → 新内容写 `wg0.conf.tmp` → `mv` 覆盖 → `chmod 600`。失败则 `.bak` 回滚。保留最近一份 .bak。
- **D9.3 生效**：首选 `wg syncconf wg0 <(wg-quick strip wg0)` 零停机；不支持或失败时回退 `systemctl restart wg-quick@wg0`。理由：生产场景已连工控机不应因加新 Peer 瞬间断线。

## 4. 菜单结构（双模式）

### 4.1 服务端 `wg-server.sh`

```
(1) 查看状态        → wg show / 握手 / 流量 / 健康提示（IP冲突、孤儿Peer、配置不一致）
(2) 添加 Peer       → 选角色(管理电脑/工控机) → 自动/指定 IP → 输入公钥 → 校验 → 原子写回 → syncconf → 回显客户端配置
(3) 删除 Peer       → 列表+序号定位 → 二次确认(+在线警告) → 原子写回 → syncconf → 善后提示
(4) 公钥清单        → 服务端公钥 + 每个 Peer 的 IP/公钥/角色对照表
(5) 启动/重启/停止/查看服务状态  → systemctl + ip_forward 检查
(0) 退出
```

### 4.2 工控机端 `wg-client.sh`

```
(1) 查看状态        → wg show / 握手 / 流量
(2) 本机公钥 / 配置 → 显示公钥、当前 wg0.conf 摘要
(3) 分流检查        → ip route get 10.77.0.1 vs 1.1.1.1（验证非全隧道）
(4) 启动/重启/停止/查看服务状态
(5) 初始化配置      → init 向导（本地生成密钥对→填Endpoint/服务端公钥/本机IP→写配置→启动并跑 ping 验证）；已有配置时提示覆盖确认
(0) 退出
```

### 4.3 子命令兜底

两个脚本都要在菜单之外支持直接子命令，菜单只是子命令的一层糖，两个入口共享内部函数。具体子命令列表见 `README.md` 命令速记表。典型如：

```
./wg-server.sh add-peer --role ipc
./wg-server.sh add-peer --role admin --ip 10.77.0.5
./wg-server.sh remove-peer 10.77.0.11
./wg-server.sh list
./wg-server.sh pubkey
./wg-server.sh status
./wg-server.sh start | restart | stop
./wg-client.sh pubkey
./wg-client.sh split-check
./wg-client.sh init
./wg-client.sh start | restart | stop
```

## 5. 典型工作流（加一台工控机）

用《使用原生 WireGuard 搭建中心化虚拟局域网》文档的术语把「从零加一台工控机」串一遍，方便 README 直接引用：

```
1. 工控机端：sudo ./wg-client.sh init
   → 选填 服务端 Endpoint、服务端公钥、本机 VPN IP(10.77.0.11)
   → 本地生成密钥对，公钥显示在屏幕
   → 写 /etc/wireguard/wg0.conf
   → 可选立即启动并 ping 10.77.0.1 验证

2. 服务端：sudo ./wg-server.sh add-peer --role ipc
   → 自动从工控机段取最小空闲 IP（如 .11）
   → 粘贴工控机公钥
   → 原子写回 wg0.conf
   → syncconf 热加载
   → 屏幕回显「客户端这样配」（服务端公钥 + Endpoint + 自己的 IP）

3. 验证：服务端 ./wg-server.sh status 看握手；工控机端 ./wg-client.sh 看 ping 与分流
```

## 6. 安全约束

私钥是这条里最容易踩的坑：

- 服务端自己的私钥：写回时原样保留，脚本不输入、不打印、不日志化
- 客户端私钥：只在工控机本机生成，永不出本机（不经网络/聊天/邮件）
- wg0.conf 及其 .bak、密钥文件一律 `chmod 600`
- 脚本拒绝 `curl | bash` 远程跑（检测 pipe/stdin），避免私钥落到不明环境
- 删 Peer 二次确认 + 在线警告，防止误踢在线工控机
- 脚本日志/输出里 **不** 出现任何私钥明文

## 7. 配置总览（脚本顶部变量）

| 变量 | 默认值 | 含义 |
|---|---|---|
| `WG_CONF` | `/etc/wireguard/wg0.conf` | 配置文件路径 |
| `WG_INTERFACE` | `wg0` | WireGuard 接口名 |
| `WG_SUBNET` | `10.77.0.0/24` | VPN 网段 |
| `WG_SERVER_IP` | `10.77.0.1` | 服务端 VPN 地址 |
| `WG_PORT` | `51820` | 服务端监听端口 |
| `ADMIN_RANGE` | `2-10` | 管理电脑段 |
| `IPC_RANGE` | `11-199` | 工控机段 |
| `RESERVED_RANGE` | `200-254` | 预留段 |
| `KEEPALIVE` | `25` | PersistentKeepalive 秒数 |
| `WG_BACKUP` | `$WG_CONF.bak` | 原子写回备份路径 |

这些都在单个文件顶部，改一处就能换网段/换端口。

## 9. 验收口径

设计完成后我自己怎么判断做对了：

- 文档 + 脚本 + README 三者术语一致（「Peer」「hub/spoke」「原子写回」「双模式」「二次确认」「在线警告」在菜单、README、DESIGN 三处叫法统一）
- 全流程闭环：从零加一台工控机（init → add-peer → 验证）全程不需要手工 nano wg0.conf
- 危险操作都有兜底：删 Peer 有二次确认 + 在线警告；写配有 .bak + 原子 mv；syncconf 失败回退 restart
- 私钥零泄露路径：脚本输出/日志里不会出现私钥；客户端私钥不经网络
- 只读项不强制 root：EUID 检测 + 优雅降级引导
